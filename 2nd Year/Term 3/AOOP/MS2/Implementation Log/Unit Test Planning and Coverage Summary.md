| Project Description | GEAR.HR is a Java Swing HR and payroll management system for employees, attendance, leave requests, user roles, and payroll processing. The application uses service classes and JDBC repository interfaces backed by MySQL (`gear.hr`). Unit tests run without a database using in-memory fakes. |


This worksheet documents the unit testing planned for the expanded MotorPH Payroll System. The goal is to identify which core logic is covered, what behavior is verified, and how unit tests protect shared business rules.

Out of scope for this document:

- GUI behavior
- Full login workflows
- Navigation or screen transitions
- Visual inspection of generated PDF layout
- Manual database installation/setup outside the application

## Unit Testing Summary

| Number of unit tests written        | 41 documented test cases; **20 implemented and executed** in the `test/` suite (`PayrollUtilsTest`, `PayrollProcessorTest`, `PayrollReportTest`, `RoleGroupTest`, `StatusEnumTest`)                                                                                                                                                                                                                                                                                                                                                                      |
| Classes covered by unit tests       | **Implemented:** `PayrollUtils`, `PayrollProcessor`, `PayrollReport`, `RoleGroup`, `LeaveStatus`, `TicketStatus`, `AttendanceStatus`, `EmploymentStatus`. **Planned but not yet implemented:** `PayrollData`, `AttendanceRecord`, `AttendanceService` (direct), `EmployeeValidationUtil`, `CredentialValidationUtil`, `Employee`, `DatabaseConnectionManager`, `PayrollJdbcRepository`, `EmployeeJdbcRepository`, `AttendanceJdbcRepository`, `UserCredentialJdbcRepository`, `ApplicationContext`, `JasperPayrollReportService` |
| Key business rules verified         | Payroll deductions follow SSS, PhilHealth, Pag-IBIG, and withholding tax rules (including bracket boundaries and allowance-inclusive taxable base); gross pay uses hourly rate multiplied by worked hours; payroll processing returns sensible results when attendance is present or absent; accounting and HR/IT roles map to the correct `RoleGroup`; department payroll summaries show the correct header, employee count, and aggregated totals; status enums parse canonical labels case-insensitively and reject invalid values safely. Planned report-export coverage verifies that JasperReports can generate a non-empty PDF from the same department-filtered payroll results. |
| Known limitations or untested areas | GUI rendering, file chooser behavior, Swing button actions, full authentication flow, visual PDF layout review, and manual MySQL setup are not covered by unit tests. JDBC integration cases (UT-23, UT-25–UT-29) depend on a running MySQL server and are documented as planned integration tests. JasperReports export (UT-41) is documented as a planned integration/report test because it depends on the JRXML template and JasperReports libraries. Validation utility, `PayrollData`, `AttendanceRecord`, and single-employee `PayrollReport.format` cases remain planned but not yet implemented. |
